Subject: SRR11526759 (PRJNA610713) types as Brucella melitensis rather than B. abortus

Dear colleagues,

We have been validating a Brucella species-identification tool against every public
Brucella read set in ENA, and one of your records came up.

    run          BioSample       deposited          the sequence says
    SRR11526759  SAMN14309819    Brucella abortus   Brucella melitensis

Three lines of evidence, from methods that share no code and no reference data:

  - Mash distance 0.00098 to the nearest B. melitensis genome in a curated 431-genome
    reference set covering all 30 named species of the clade. That is as close as two
    genomes of one species normally get.
  - MLST-9 (Whatmore et al.) sequence type 8, which the PubMLST isolate database
    records as B. melitensis in 98.3% of the 862 isolates carrying it.
  - The B. melitensis real-time assay of Hoover et al. 2026
    (doi:10.1128/spectrum.02974-25), run in silico, is held in full while the
    B. abortus assay is absent. In silico Bruce-ladder independently gives a
    melitensis pattern.

The library itself is sound - it assembles to 3.28 Mb, the normal size for a Brucella
genome - so this looks like a good genome with a different species name on it rather
than a data problem.

If you agree, updating the organism field on the BioSample would correct it
downstream; those records feed reference databases, which is how we met yours. If you
disagree I would genuinely like to know: the physical isolate outranks the sequence,
and the sequence outranks our reading of it.

Every per-record verdict is public at https://github.com/duceppemo/BrucellaID under
curation/, including the errors we found in our own reference set in the same pass.
Happy to send the assembly, the allele calls or the distance table.
